# AI Concepts Playground

Fifteen runnable demos for machine learning and LLM engineering, in two parts:

- **Part 1 — Foundations.** The algorithms, written **from scratch with NumPy**. No scikit-learn,
  no PyTorch, no hidden steps.
- **Part 2 — LLM engineering.** Embeddings, tokenization, prompting, retrieval, tool calling and
  evaluation, built on a **deterministic mock model** so everything runs with no API key and no
  network.

Every demo **runs**, every claim is **tested**, and every number quoted in the write-up was printed
by the code in this repository.

```bash
pip install -r requirements.txt

python run_all.py            # run all 15 demos, write the plots
python -m pytest tests -q    # 45+ assertions that fail if an algorithm changes behaviour
python tools/build_site.py   # build the static site into dist/

python -m mlconcepts.foundations.neural_network   # or run a single demo
```

## Why this exists

Machine learning is usually taught two ways, and both leave a gap.

Tutorials that call a library show you the API and hide the thing you actually wanted to learn.
Papers show you the maths and assume you will implement it yourself. This repository is the missing
middle: **short, readable implementations of the ideas, each one runnable, each one tested.**

The tests are the point. They do not check that the code runs — they check that it is *right*:

```python
def test_gradient_descent_finds_the_mean():
    y = np.array([1.0, 3.0, 5.0, 7.0])
    w, history = what_is_ml.fit(y, learning_rate=0.1, steps=500)
    assert abs(w - y.mean()) < 0.01

def test_a_hidden_layer_beats_a_linear_model_on_a_ring():
    ...
    assert linear_accuracy < 0.8      # a line cannot wrap around a ring
    assert net_accuracy > 0.9         # a hidden layer can
```

## Live site

**https://vishnuu12.github.io/AIConceptsPlayground/**

Every push to `main` runs the demos, runs the tests, rebuilds the site and republishes it. If a demo
raises or a test fails, nothing is published — a broken demo can never appear as a working one.

The site is plain HTML generated by `tools/build_site.py`, so there is no JavaScript framework to
break. It uses **relative links throughout**, which is what makes it work under `/<repo>/` on Pages.

## How to read this

1. **Run the demo before reading the page.** The trace prints real numbers, and they are easier to
   believe once you have watched them appear.
2. **Read the module docstring.** It is the "why" — what breaks without the concept.
3. **Break it.** Set the learning rate to 5. Set `k=7` on three clusters. Remove the overlap from
   the chunker. Then run the tests and watch which one catches you.
4. **Do the interview questions last.** They are there to check you can say it, not just recognise it.

## Honesty notes

These are stated plainly because a repo that overstates what it contains is worse than a smaller
honest one.

- **The model in Part 2 is a simulator.** It pattern-matches keywords, pulls sentences out of a
  supplied context, and emits tool calls for known verbs. It does not understand language. The
  *engineering* around it — chunking, retrieval, prompt assembly, the tool loop, the eval harness —
  is real and is exactly what you would write against a real API.
- **The embeddings in Part 2 are feature hashing**, not a trained model. They capture shared words,
  not meaning, so `cos('car', 'automobile')` is 0.0. Everything else on that page is identical with
  real embeddings, and the page says so.
- **No GPU, no large models.** Every demo is deliberately tiny so it runs in seconds on a laptop.
  You will understand the mechanics here; you will not train a production model here.
- **A repo is a scaffold, not a course.** It is built to be read alongside a textbook or a course,
  not instead of one.
